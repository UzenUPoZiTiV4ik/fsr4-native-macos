# v3.2: ANR hook startup fix and experimental new-look

v3.2 fixes an ANR hook startup crash and adds an optional new look for
FSR 4.1.2 Lite Lossy. The default remains **FSR 4.1.2 Lite**. No neural
model weights or default processing modes change.

## Fix: ANR selected at startup

- The v3.1 live-switch hook could crash while loading when ANR was already
  selected: its constructor accessed C++ containers before their translation
  unit had initialized them. Runtime state is now created on first access
  and kept for the process lifetime, independent of link order.
- Installer smoke/dlopen checks now test the **requested FG engine**, not
  accidentally only MetalFX. New Rosetta startup regressions load the
  constructor before the runtime and check ANR/MetalFX, settings-file and
  environment overrides, status output and background-controller ticks.
- No model, Metal device or GPU work is needed during hook initialization.
  Native MetalFX passthrough and live switching are retained.

## New: Experimental new-look for Lite Lossy

Select **FSR 4.1.2 Lite Lossy** in the panel, then enable the orange
**Experimental new-look** checkbox. It is **off by default** and available
only after the optional Lite Lossy weights have been prepared with
`make lite-lossy-weights`.

- New history rules for compact bright particles, per-channel sparks,
  thin lines, depth-edge flecks, persistent changes and slow fades.
- Independently implemented from [cyboman's public issue #20 explanation](https://github.com/UzenUPoZiTiV4ik/fsr4-native-macos/issues/20#issuecomment-6839502725);
  the GPL shader generator is not imported. This is a visual experiment,
  not a new neural model or an FSR speedup.
- The preference is saved separately as `new_look=0|1`. Sharpness, RCAS,
  Pixelization fix, SR profile and MetalFX/ANR selection remain independent.
  Switching new-look resets history and uses a separate shader-cache identity.
- CLI: `tools/bin/fsr4mac CASE OUT --fsr-version 4.1.2 --profile int8-lite-lossy --new-look`.

**Limits:** whole-frame Lite Lossy, linear input and output up to 4K only.
Tiled, original-graph and nonlinear/sRGB/PQ variants are not supported.
This is not verified bit-for-bit parity with the Windows DLL. Real-game
quality and HDR have not been verified. Turn it off if the result is worse;
ordinary Lite Lossy, Lite, Exact and ANR are unchanged with the option off.

Recorded M5 synthetic diagnostics show small gains on wires and bright
particles, and a larger gain on dark particles, but a **moving-object
regression**: PSNR 44.59 -> 43.33 dB and temporal error about +9.9%.
A short interleaved 1080p diagnostic measured GPU median 6.29 -> 6.56 ms
(about +4.3%). These are not game FPS or sustained thermal measurements.
[Full conditions, results and limitations](../FSR412_NEW_LOOK.md).

## Update

Quit the game and reinstall from the new ZIP or DMG, then restart the game.
Changing source files does not update the hook already installed in a bottle.
ANR model/kernel assets remain local-only and are not included in the release;
see the [ANR setup and limitations](../ANR_RESEARCH.md).

## Checks

- `make test`: host/settings/installer suites and Python regressions, including
  the no-model ANR startup checks.
- `make test-fsr4-panel-ui`: real AppKit checkbox interactions and layout.
- `make test-fsr412-new-look`: 1002 scalar-rule cases on real Metal 3/4,
  MPP/scalar/SIMD output/history/recurrent parity, resets, mode switching
  and Ultra Performance. The disabled transform is byte-identical to v3.1.
- `make test-anr-ui`, `make test-anr-motion`, `make test-anr-live` with local
  ANR assets: Metal 3/4, live switches, queued frames, HUD safeguards and HDR.
