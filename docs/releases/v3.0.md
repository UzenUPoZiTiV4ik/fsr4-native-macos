# v3.0: quality/performance panel and heat-aware model measurements

## FSR 4 Panel

- Replace the mode segments with a discrete **Quality -> Performance** slider.
  The current model name is shown above it; each tick is a different processing mode.
- Apply one mode when the slider is released, rather than preparing every
  intermediate model crossed while dragging. Sharpness, RCAS and Pixelization
  fix/strength remain separate controls and retain their saved values.
- The panel explicitly explains in English: **render and output resolution
  stay unchanged**, switching may cause stutters or pauses, and users should
  try different modes to find the best quality/performance balance for their game.
- Left-to-right is a suggested trade-off, not a measured quality ranking or
  a guarantee that every next model is faster on every game/device.
- **Lite Lossy Tiled is removed from the panel choices.** Its experimental
  `int8-lite-lossy-tiled` CLI profile and saved ID 8 remain readable for
  compatibility. A saved unavailable/retired mode is not silently replaced
  when Sharpness or RCAS changes; choose another mode explicitly to leave it.
- Optional Lossy/Lite Lossy models still require their external inputs. The
  ordinary Lite initializer is never substituted for the trained one.

## Fresh 1080p and 1440p measurements

All 12 model/option variants were measured with **native MPP and forced
SIMD** on a fanless **MacBook Air M5, 16 GB**, at **1280x720 -> 1920x1080**
and **1706x960 -> 2560x1440**. Auto-exposure on, RCAS off. These are M5
measurements, not M1-M4 performance. M5-only POST optimizations remain enabled;
the legacy 4.0.2 SIMD column uses its real FP16 encoder.

- Resolution order: 1080p, 1440p, 1440p, 1080p. Inside each process all models
  run serially; the first model rotates and direction reverses each frame.
- Initial 120-second warmup per resolution, 30-second warmup on repeat passes.
  Compilation, pipeline creation, allocations and warmup frames are excluded.
- Per model/backend/resolution: **12 rounds x 64 frames = 768 measured frames**.
  The headline number is the median of all round means, not the best/cold run.
- MPP measured rounds were **fair**; SIMD spanned **nominal/fair**. The later
  1080p Lite series was about **20% slower in MPP and 18% slower in SIMD**
  than its earlier warmed series. Both passes are included with round ranges,
  not discarded in favour of the faster run.
  Early/late drift, P99 and full/reused/partial costs are saved. No privileged
  temperature/frequency readings are claimed; thermal state is not a thermometer.
- These are whole-upscaler GPU command-buffer times on one deterministic
  synthetic scene, **not game FPS** or a guarantee for other scenes/Macs.
  Reuse-eligible modes use a stable 50:50 full/reuse schedule.

## Compatibility and checks

This release changes the panel and reporting, not the neural kernels,
weights, default profile or live-hook ABI. The default remains
**FSR 4.1.2 Lite**. macOS 27/Xcode and CrossOver fixes from v2.6 are retained.

- `make test`: CPU/model, CrossOver, cache, settings and installer tests.
- `make test-fsr4-panel-ui`: native AppKit clicks, tick bounds, release-only
  application, saved settings, recovery from a retired profile and layout.
- `make test-gpu`: native, fallback, SIMD/Winograd, runtime and live-hook suites.
- `make test-fsr412-lossy`: native/scalar/SIMD state parity on classic Metal
  and Metal 4, including the experimental partial path.
- `make test-fsr412-original`: output/history/recurrent/reprojected/scratch
  identity against the original-shader oracle, including Metal 4 and 4K.
- No games or Windows DLLs were started for measurements or validation.

## Install/update

Open **FSR4-Installer-v3.0.dmg**, or unpack
**fsr4-mac-v3.0-crossover.zip** and follow `INSTALL.md`.
Quit the game and its bottle, install again, then restart the game to load
an updated hook/panel. Existing panel files and caches are kept. Choose your
preferred startup mode when reinstalling (the CLI uses `--profile`); the new
panel itself does not silently replace saved modes on unrelated control edits.
Sharpness, RCAS and fix strength remain separate saved settings.

The installer is ad-hoc signed, not notarized. On first launch macOS may
require **System Settings -> Privacy & Security -> Open Anyway**.

Trained Lossy data and original-shader bundles stay an explicit external
fetch under `build/`. No GPL-derived initializer, translated original
shader bundle or Windows driver DLL is added to the release ZIP/DMG.
