# v4.0 - Faster everything: Lite Lossy reuse, wider Winograd, MPP fast paths, codebase restructure

Quit the game, install the new DMG or CrossOver ZIP, then restart the game. No model or weight changes: every profile keeps its v3.3 data and its pinned upstream inputs. The first launch recompiles the optimized shaders for the game's resolution (tens of seconds once, then cached).

## What changed

**Lite Lossy POST/PRE slimming** (`int8-lite-lossy`, panel **FSR 4.1.2 Lite Lossy**):

- The reuse cache is compacted from 32 to **16 bytes per pixel** (half-precision
  filter parameters instead of raw integer logits), halving cache traffic; the
  exponential re-evaluation of recurrent/filter parameters on reused frames is
  gone. Numerical output is preserved by construction and verified below.
- POST is split into specialized **post_full** and **post_reuse** kernels instead
  of one kernel carrying both frame kinds in registers; whole-frame mode picks
  the right one per frame, partial tiled mode keeps the unified POST.
- The nine prepared/working colour taps of the temporal filter are loaded once
  into registers per thread instead of per use, the 2x2-cell classification
  reads are shared across the cell, and cache writes are coalesced.
- PRE neural tail: the 2x2 quad now exchanges its packed half inputs with three
  `quad_shuffle_xor` rounds and each lane computes 4 of the 16 downscale
  channels (previously every lane computed all 16 and discarded three quarters).
  The reduction order is preserved exactly, so the scratch output is bit-exact
  on even and odd resolutions.
- `pre_reuse` keeps its own specialized bundle; cache keys move to `_lossy4`,
  so stale compiled bundles are rejected automatically.

**Wider exact Winograd on the SIMD backend** (M1-M4 path, forced-SIMD on M5):

- F(2x2, 3x3) now covers CT32 and the NF64/CT64 16-channel banks in addition to
  CNB16/FNB32, for every 3x3 block that passes the per-pass lossless bound
  gate; DS blocks stay direct. Interior rows are loaded once per tile instead
  of per vertical transform. Weights are transformed at load time per bank.

**Probe-verified MPP fast paths** (M5 INT8 tensor path):

- New `*_coop_fast_*` kernels drop per-tile layout checks, `simd_all` barriers
  and the scalar fallback: interior tiles skip per-quartet bounds checks and
  batch all residual loads before output stores to eliminate alias stalls.
  A runtime probe (`fsr411_mpp_chain_probe`) verifies every cooperative tensor
  layout contract first; unverified devices/toolchains and old caches keep the
  established kernels.
- Two wider chain shapes (`cnb 32x2`, `fnb32 32x1`) reduce pass count.

**Codebase restructure** (no production feature removed):

- `src/`, `tools/` and `tests/` are organized into subsystem folders
  (`fsr41x`, `fsr402`, `anr`, `netal`, `live`, `common`, `installer`, `bench`,
  `crossover`) with no loose root files; the duplicated FSR runtimes and unused
  shader sources are merged or removed.
- Legacy research tooling is trimmed: M5 bring-up probes, orphaned benchmarks,
  one-off vendor scripts and the upstream-oracle cluster. Own code drops from
  48.5k to about 37k lines (-24% across the two cleanup commits); the Makefile
  compacts from 535 to 421 lines with unified test discovery.

## Compatibility

- No weight, model or panel-ID changes. The external optional data commands are
  unchanged (`make lite-lossy-weights`, `make lossy2-weights`, ...); already
  fetched data remains valid.
- Compiled shader bundles are invalidated by revision bumps (`lossy3` ->
  `lossy4`, new POST specialization keys) and rebuilt on first use per
  resolution. Nothing to do manually.
- Hook ABI, bottle keys and the installer flow are unchanged from v3.3.

## Validation

- Native GPU comparisons: 52/52 byte-identical cases across passes 1-12 and
  post_cnb at several tile shapes (MPP/SIMD vs reference).
- Shader-generation suites: 38 passed, 1 skipped (lossy POST/PRE rewrites, CT2D,
  new-look, reset/clear).
- Installer check on macOS 27.0.1, Apple M5: x86_64 hook under Rosetta, live
  720p -> 1080p output matches the command-line reference at every pixel.
- Game FPS and game image quality have not been measured for v4.0; the numbers
  above are GPU-time replays of a synthetic input contract.
