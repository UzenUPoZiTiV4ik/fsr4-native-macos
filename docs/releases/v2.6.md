FSR 4.1.2 Lite Lossy, an original-shader route, and macOS 27 / CrossOver fixes.

### Lite Lossy (optional)
- New `int8-lite-lossy` profile: the upstream `dll-2026-11-01` Lite Lossy
  trained weights, decoded statically from the pinned DLL. The initializer and
  import receipt stay in `build/fsr412_lossy`, outside this MIT repository;
  `make lite-lossy-weights` fetches and verifies them.
- Whole-frame inference reuse, plus an experimental `int8-lite-lossy-tiled`
  cadence that refreshes half of the 128..2048-pixel tiles per frame with a
  convolution halo and ping-pong parameters.
- Panel and installer offer both modes as IDs 7 and 8. They appear only when
  the pinned inputs are present, and an install never falls back to the
  ordinary Lite initializer.

### Original-graph route (`int8-lite-lossy-original`, opt-in)
- Runs the release's own PRE, P1-border, BORDER and POST shaders (statically
  translated, IO-guarded, kept under `build/`) and replaces only the CNB, DS,
  FNB and CT stages with the exact native INT8 kernels.
- Production `Runtime::encode` matches the original-shader oracle byte for
  byte on every frame: output, history, recurrent, reprojected and the whole
  logical scratch, for MPP, SIMD and scalar on classic Metal and Metal 4,
  at 640x384, 644x388, 1920x1080 and 3840x2160, including reused frames.
- Run-frame POST reads a native-precomputed CNB for the proven
  2160/normal/auto-exposure permutation: the 4K full frame drops from 36.0 to
  14.9 ms. Other permutations and reused frames keep the original POST.
- Three real defects came out of this work: Metal `-O3` miscompiles the
  original P2 (the reference now compiles P2/P3 at `-O0`), the auto-exposure
  permutation classifier was inverted (bundle revision 2 rejects stale
  caches), and the neural halo is class-sized, not viewport-sized.

### Correctness fixes in the shared Lite path
- Conditional POST first-tap biases and per-subpixel CT biases now match the
  source; cache revisions reject older, silently wrong bundles.
- Optional Lite POST colour tiles (Apple10 only) with a `noinline` read that
  keeps M5 fast-math from changing the picture.
- Legacy FSR 4.1.1 Lossy gains optional fine-motion and persistent-change
  repairs, plus a fast note-only mode. Both are opt-in.

### macOS 27 and CrossOver
- Builds with the macOS 27 SDK and Apple clang 21 (issue #19).
- CrossOver 26: D3DMetal is found under `lib64` as well as `lib`
  (issue #15), and the version shown for an existing install no longer comes
  from a stale bottle key (issue #14).
- Bottles on an external drive are discovered again (#11), and any CrossOver
  name or folder is accepted.
- The Swift installer now passes Xcode's platform macro plugins to `swiftc`
  when the toolchain does not add them itself, which fixes
  `@State`/`@Bindable` expansion failures on current Xcode.

### Compatibility and checks
- Plain `int8-lite`, `int8-lite-pixfix`, FSR 4.1.2 Lossy, FSR 4.1.1 Exact and
  Lossy2 output is byte-identical to v2.5 on the recorded scene.
- `make test`, MPP fast/fallback, SIMD/Winograd, Lite Lossy and the
  original-graph A/B pass on classic Metal and Metal 4. The installer strings,
  CrossOver tests and the x86_64 live hook checks pass.
- Windows driver DLLs are neither bundled nor executed; the original route is
  a Metal translation of the extracted shaders, not a Windows parity claim.

### Install/update
Open **FSR4-Installer-v2.6.dmg**, or unpack **fsr4-mac-v2.6-crossover.zip** and
follow `INSTALL.md`. Quit the game and its bottle, run Install again, then
restart the game to load the updated hook. An existing install keeps its
saved panel mode.

The installer is ad-hoc signed, not notarized; macOS may require
**System Settings -> Privacy & Security -> Open Anyway** on first launch.
