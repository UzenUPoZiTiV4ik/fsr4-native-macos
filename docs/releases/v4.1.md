# v4.1 - ANR FG-V.B20, 3x frame generation, and M5 Metal 4 MPP optimizations

Quit the game, install the new DMG or CrossOver ZIP, then restart the game.
FSR 4.1.2 upscaler profiles, weights, and shader caches are unchanged from v4.0.
To use the updated ANR frame generator, prepare a local runtime from the upstream
`anr-fg-V.B20-addon.zip` (ANR weights and compiled shaders remain local under
`build/` and are never packaged in this repository or release archives).

## Measured ANR speedups (Apple M5, 1080p interleaved A/B)

Interleaved A/B GPU timings on Apple M5 comparing the optimized V.B20 runtime
against unoptimized V.B20 and the previous V.B14 `packed` runtime (standalone
replay, not guaranteed game FPS):

| Comparison (1080p interleaved A/B) | Speedup (`B/A`) | Quality (`verify.py`) |
| --- | ---: | --- |
| `V.B20 opt` vs `V.B20 unopt` (2x) | **+17.6% to +21.1% faster** (`0.7888..0.8244`) | `73.10 dB` at `t=0.5` (gate `72.0 dB`) |
| `V.B20 opt` vs `V.B20 unopt` (3x) | **+14.4% to +19.6% faster** (`0.8044..0.8558`) | `72.30 dB` at `t=0.75` (gate `71.0 dB`) |
| `V.B20 opt` vs legacy `V.B14 packed` (2x) | **+11.7% faster** (`0.8828`) | Dynamic `640x360..7680x4320`, native `srgb8`/`pq10`/`scrgb16` |

At M5 boost clocks, 1080p 2x standalone inference runs in **~3.85 ms**
(`pair=1.91 ms`, `phase=1.89 ms`), beating legacy V.B14 while supporting
arbitrary resolutions and native color formats.

## What changed

**ANR FG-V.B20 dynamic runtime (`fsr4_anr_runtime_v2`)**:

- `tools/anr/prepare.py --addon /path/to/anr-fg-V.B20-addon.zip --output build/anr_runtime_v20`
  extracts the upstream `packed` dynamic graphs (`version: 3`) and translates
  SPIR-V kernels via `spirv-cross` + Xcode's Metal compiler (no Apple Metal
  Shader Converter SDK required).
- Evaluates dynamic expression/guard graphs at runtime for any resolution from
  **`640x360` to `7680x4320`** (including odd/non-standard display sizes such as
  `1710x1073`), eliminating the legacy 1080p/1440p/2160p-only restriction.
- Native **`srgb8`**, **`pq10`**, and **`scrgb16`** encodings match the game's
  actual pixel format (`RGBA8`/`BGRA8`, `RGB10A2`, `RGBA16F`), avoiding SDR/PQ10
  round-trip conversion overhead in the live bridge.
- Fixed sampler address mode (`MTLSamplerAddressModeClampToZero`) in `src/anr/anr_runtime.mm`
  to match upstream out-of-bounds zero clamping.

**Experimental 3x frame generation (`anr3x`)**:

- On V.B20 runtimes, `anr3x` executes the pair-encoder pass once and generates
  two intermediate frames (**`t=1/3`** and **`t=2/3`**) on the same command buffer.
- `t=1/3` writes to MetalFX's output texture; `t=2/3` writes to a ticketed
  per-slot texture and is inserted right after `t=1/3` via a lazy presentation
  hook (`CAMetalDrawable` + `MTL4CommandQueue` on Metal 4, `MTLCommandBuffer`
  on Metal 3) with EMA-smoothed `1/3` frame pacing and automatic 3-drawable
  pool expansion.
- The presentation hook is installed lazily only when `ANR 3x` is activated;
  `MetalFX` and `ANR 2x` incur zero presentation-hook overhead.
- `FSR4 Panel.app` now provides a 3-segment **MetalFX | ANR 2x | ANR 3x**
  selector with live multiplier, release, encoding, MPP status, and `+extra`
  counter. Switching live between `ANR 2x` and `ANR 3x` on V.B20 keeps views
  and pipelines warm (no reload hitch).
- `tools/crossover/crossover_fsr4.py` supports `anr3x` in both `install --frame-generation anr3x`
  and `frame-generation anr3x`.

**M5 GPU & runtime optimizations**:

- **Metal 4 MPP NAX `conv_packed_m1`** (`kernels_mpp.metallib`): native
  `mpp::tensor_ops::matmul2d` implementation with register `cooperative_tensor`
  accumulators and 15.5 KB `threadgroup union` aliasing (2x occupancy on M5).
  Activated automatically on `MTLGPUFamilyApple10` (M5+), with automatic
  fallback to `kernels.metallib` on M1-M4 (`FSR4_ANR_MPP=0` to force fallback).
- **Compiler & threadgroup optimizations**: strips `[[clang::optnone]]` barriers
  around SPIR-V Cross FP arithmetic across all 33 kernels (`strip_optnone_msl`),
  replaces non-atomic threadgroup accesses in gather shaders with plain loads/stores,
  and sets `threadGroupSizeIsMultipleOfThreadExecutionWidth = YES` on 32-aligned
  kernels.
- **Runtime & live bridge efficiency**: read/write dependency DAG barrier elision
  (`FSR4_ANR_DAG_BARRIER=0` to disable), cached per-slot `MTLResidencySet`s,
  zero-conversion direct color import/export, and `anr_import_dm` for cases where
  only depth/motion need format or resolution conversion.

## Compatibility

- FSR 4.1.2 upscaler models, weights, profiles, and compiled caches are
  unchanged from v4.0.
- Legacy `FG-V.B14` runtimes (`1920x1080`, `2560x1440`, `3840x2160`) continue
  to work for 2x; selecting `ANR 3x` with a V.B14 runtime safely stays in 2x
  and reports the requirement in `fg-status.conf`.
- Preparing `build/anr_runtime_v20` from `anr-fg-V.B20-addon.zip` requires
  `spirv-cross` (e.g. `brew install spirv-cross`) and Xcode's Metal Toolchain.
- Point a bottle at the prepared runtime with:
  ```sh
  python3 tools/crossover/crossover_fsr4.py frame-generation anr \
    --anr-runtime "$PWD/build/anr_runtime_v20" --bottle "YourBottle"
  ```

## Validation

- `make test`: 247 unit, installer, panel-settings, and Rosetta `dlopen` startup
  tests passed (including `metalfx`, `anr`, and `anr3x` startup/override modes).
- `make test-anr-ui`: 16/16 Metal 3 and 16/16 Metal 4 UI recomposition cases passed.
- `make test-anr-live`: passed on Metal 3 and Metal 4 (both native arm64 and
  Rosetta `x86_64`) at `1920x1080` (PQ10 and linear HDR) and `1710x1073` (native
  `srgb8` SDR), verifying live `MetalFX <-> ANR 2x <-> ANR 3x` switching,
  `CAMetalLayer` 3x extra-frame presentation, 8,192 exact HUD pixels, and unsafe
  UI rejection.
- `make test-anr-motion`: passed on Metal 3 and Metal 4, confirming accurate
  object motion positions at `t=0.5` (2x) and both `t=1/3` and `t=2/3` (3x).
- `tools/anr/verify.py`: passed both reference PSNR gates (`73.10 dB` vs `72.0 dB`
  at `t=0.5`; `72.30 dB` vs `71.0 dB` at `t=0.75`).
- Live CrossOver game smoke observation on Apple M5 (`1710x1073`, `srgb8`,
  `FG-V.B20`, `mpp_active=1`): 2,857 generated 2x frames with 0 fallbacks and
  adaptive precomposited HUD active. In-game 3x pacing across diverse titles
  remains experimental.
