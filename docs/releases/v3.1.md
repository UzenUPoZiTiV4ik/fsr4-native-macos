# v3.1: experimental ANR frame generation

v3.1 is v3.0 plus a new, **experimental** frame generation engine. FSR
upscaling models, weights, the default profile (FSR 4.1.2 Lite) and the
Quality -> Performance panel are unchanged from v3.0.

## New: ANR frame generation (experimental)

- An independent ANR runtime can replace the **MetalFX frame interpolator
  that D3DMetal uses for DLSS Frame Generation** in CrossOver. Output is 2x
  (one generated frame between two rendered frames).
- The FSR 4 panel has a new **Frame generation: MetalFX / ANR** switch with
  an orange "experimental" warning and a live FG status line (active, generated
  frame count, HUD handling, or the reason it fell back to MetalFX).
  The switch applies while the game runs (checked twice per second) and does
  not touch the SR mode, sharpness or RCAS. DLSS Frame Generation must still
  be enabled in the game.
- HUD/UI handling: precomposited UI is recomposited adaptively so the HUD
  does not smear or flicker between the generated and the real frame. Unsafe
  UI layouts (aliased output, mismatched formats) keep the original MetalFX.
- **MetalFX mode is a true passthrough:** the original Apple encode runs, no
  ANR kernels, imports or barriers. A Rosetta A/B on M5 measured +0.63% (Metal 3)
  and -0.62% (Metal 4) GPU median against an unhooked process, within run
  variation ([report](../reports/metalfx-passthrough-m5.json)).
- Measured M5 ANR inference at `t=0.5` (standalone replay, not game FPS):
  about 3.8 ms at 1080p, 6.9 ms at 1440p, 14.8 ms at 4K with the packed graph.
- CLI: `crossover_fsr4.py frame-generation metalfx|anr --bottle ...`;
  `restore` also removes the ANR keys.

**Limits.** ANR model/kernel assets are **not distributed**: they are prepared
locally from the FG-V.B14 test kit ([setup](../ANR_RESEARCH.md)). Without them
the panel switch stays on MetalFX. Image quality and frame pacing in real games
are not yet verified; expect artifacts and judder in some scenes.

## Other changes

- `FSR4_REPLACE=0` no longer swizzles SR methods at all (verified by the
  installer smoke test).
- The upscaler hook caches descriptor flags at creation and still reads
  changing offsets every frame.
- Experimental Netal DLSS SR support stays in the source but is hidden from
  the panel and README for now.
- README: the upstream lossy project is now called the "FSR 4 performance
  project" (it covers RX 6000, integrated GPUs and the Steam Deck too).

## Upstream review

The upstream `dll-2026-11-01` / `dll-2026-11-05` releases speed up the
Windows/AMD DXIL Lite builds (shared color samples, a separate border-clear
shader, skipping passes with no picture effect). They contain no new weights.
The Metal paths here already have opt-in shared color tiles, and pass 2 is a
native INT8 kernel without the class-sized grid behind upstream's 1440p gain,
so nothing was ported.
